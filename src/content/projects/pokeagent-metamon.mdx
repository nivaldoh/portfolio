## A Metamon and PokéChamp hybrid

Metamon is an offline-RL agent trained on human battles; PokéChamp is an LLM agent that searches a minimax tree. PokéChamp's search can look ahead with a battle simulator, but judging a position means asking an LLM for a score, while Metamon has learned from human battles which moves are likely and how likely a position is to be won. In late October 2025 I combined them in [a fork of PokéChamp](https://github.com/nivaldoh/pokechamp/tree/fb520c95a298518c929adb09cc4c105b68b29f3e). Metamon's policy proposes our candidate moves, PokéChamp predicts the opponent's replies and plays each pair one turn ahead, Metamon's critic scores every resulting position, and minimax takes the move whose worst case is best. A turn needs no LLM call; an earlier version still asked the LLM for the candidate moves.

<HybridSearch />

The hard part was the bridge between the two codebases. Metamon reads a battle as a sequence of observations, so [`metamon_bridge.py`](https://github.com/nivaldoh/pokechamp/blob/fb520c95a298518c929adb09cc4c105b68b29f3e/pokechamp/metamon_bridge.py) mirrors every message of the live battle into Metamon's trajectory format, normalises the simplified messages the simulator emits, and clones that context for every simulated branch, so the critic scores each leaf with the history that led to it. I kept no search logs, so the scores in the diagram are illustrative.

## Competition repository and experiments

For experiments, I packaged Metamon self-play as a container image that runs as a Cloud Run Job. The image bundles Metamon, AMAGO and a built Pokémon Showdown server. Each task starts its own Showdown server on localhost, waits until it answers, and then runs battles between two Metamon agents logged in as different users.

A task manifest names the agents, format, teams and requested battle count. Each worker reads its own row, loads pretrained models or local checkpoints, and saves trajectories under a separate run and task path.

<SelfPlayDiagram wide />

The design choice that shaped the rest was keeping every task self-contained. With a private Showdown server in each container, tasks share nothing while they run, so adding tasks needs no coordination between them. Workers only load checkpoints and only write trajectories. Training on those trajectories is a separate step: the runner prints the training command rather than launching it.

The repository shows what the pipeline does, not how much it ran. It contains no run logs, so I make no claim here about the number of battles it produced or what they cost. The same repository also holds training-side experiments from the competition period, including a [win-probability head](https://github.com/nivaldoh/metamon_pokeagent_comp/blob/3c54f02f9bfd718f4081c1b377346efedd236cd6/metamon/rl/win_probability_head.py) that reads the agent’s sequence encoder and checkpoint uploads to Cloud Storage during training. None of them is documented as part of a tournament entry, and I don’t report results for them.

<Details summary="How a task finds its configuration">

The image is built with Cloud Build and pushed to Artifact Registry. Its entry point is `tini -- with-showdown run-self-play`: [`with_showdown.sh`](https://github.com/nivaldoh/metamon_pokeagent_comp/blob/3c54f02f9bfd718f4081c1b377346efedd236cd6/docker/with_showdown.sh) starts the Showdown server on `127.0.0.1` and polls it every half second, for up to 90 seconds, before handing over to the runner.

[`run_self_play.sh`](https://github.com/nivaldoh/metamon_pokeagent_comp/blob/3c54f02f9bfd718f4081c1b377346efedd236cd6/docker/run_self_play.sh) reads line `CLOUD_RUN_TASK_INDEX + 1` of the manifest named in `JSONL_TASK_MANIFEST` and exports its fields as environment variables. One line of [`selfplay_rlv2.jsonl`](https://github.com/nivaldoh/metamon_pokeagent_comp/blob/3c54f02f9bfd718f4081c1b377346efedd236cd6/manifests/selfplay_rlv2.jsonl), formatted for reading:

```json
{
  "battle_format": "gen1ou",
  "agent1": "SyntheticRLV2",
  "agent2": "SyntheticRLV2",
  "team_set": "competitive",
  "num_battles": 6000,
  "cfg_tag": "gen1ou_SyntheticRLV2_SyntheticRLV2_competitive"
}
```

`num_battles` is a requested setting, not a record of battles played. The output path is `/selfplay/run=<UTC run id>/cfg=<cfg_tag>/task-<index>`, with separate `agent1/` and `agent2/` directories for each format. A local agent is given as a checkpoint directory, an epoch and its model and training configuration files instead of a pretrained name. The second agent starts a few seconds after the first, five by default.

</Details>

## Metamon contributions

Two of my pull requests were merged into Metamon:

- [**#65, Team prediction improvements**](https://github.com/UT-Austin-RPL/metamon/pull/65), merged on 31 January 2026 into the maintainers’ staging branch and carried forward to `dev` the next day; its validator is now on `main`. Team validation reuses one persistent Showdown validator process instead of starting one for each item. Usage-statistics aggregation can filter data by a Smogon rank baseline. The Smogon scraper, which was timing out on some files, gained exponential backoff and a concurrency limit.
- [**#70, Fix error when creating usage stats JSON files**](https://github.com/UT-Austin-RPL/metamon/pull/70), merged on 1 February 2026: a follow-up fix once #65 reached `dev`.

These came out of a formal appointment at UT Austin's Robot Perception and Learning Lab in early 2026, with weekly meetings with Jake Grigsby. A third piece of work was an experiment: it started as timestep-encoder profiling in [#78](https://github.com/UT-Austin-RPL/metamon/pull/78) and continued as #111 in the lab's private development repository. It rewrites the grouped timestep encoder so that it keeps working under `torch.compile`'s `reduce-overhead` mode (CUDA graphs); in my A/B runs the rewrite was about 10% faster than the encoder it replaces. It also adds a profiler that accepts a candidate change only if its outputs match the baseline's and it is no slower, so that a coding agent could try many small optimisations and keep only the ones that pass.
